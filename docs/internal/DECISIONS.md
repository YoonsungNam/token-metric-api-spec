## 1. 체계의 골격 (초기 확정)

- **목적**: 기존 토큰 API(토큰·requests) 위에 **모델별 GPU Hour + 성능 메트릭(TTFT·ITL·Output TPS)** 을 추가 수집 → 비용·효율·성능을 한 화면에
- **설계 원칙**: ① 이중 소스 금지 ② 기존 계약 상속(pull, 식별자, 응답 규칙) ③ 담당자 부담 최소(서비스당 GET 1개)
- **수집 경로**: GET `/v1/metrics` daily pull (`409`로 "0"과 "미확정" 구분) + vLLM/SGLang은 중앙 Prometheus 스크랩(구현 불필요) — 케이스 A~F 가이드
- **비용**: 정본은 **할당**(GPU 대시보드) × 기종 단가. gpu 블록은 할당 비용의 용도 분해(serving/standby/test — 유휴는 중앙 산출). 효율 지표는 serving만 사용
- **사내 플랫폼 소비**: GPU는 돌리는 쪽만 제공(단일 제공 원칙), 소비자 식별은 공급자 책임(서비스 계정), 배부 키는 가중 토큰(input×1 + output×4), standby·test·유휴는 배부 제외(플랫폼 오버헤드)
- **모델명 정규화**: canonical + alias. "다르게 불리는 같은 것은 합치고, 같게 불리는 다른 것은 나눈다." 판단 3문항(웨이트/순정/정밀도), `-ft-{용도}` 필수 분리, 애매하면 나눔

## 2. 논의로 확정된 결정 사항 (시간순)

| # | 쟁점 | 결정 | 근거 |
|---|---|---|---|
| 1 | 관리 정보 관리 방식 | 레지스트리 등록 화면 → **엑셀 취합** (1단계). 등록 화면(웹 폼+DB)은 향후 전환 검토 | 1단계 진입 장벽 최소화 |
| 2 | 취합본 갱신 유지 | 담당자 기억이 아닌 **중앙 감지 알림** 기반 — 미등록 모델 유입·engine 자기신고 불일치·검증 위반·할당 매핑 불일치를 시스템이 잡아 알림 | 수기 갱신은 유지되지 않음 |
| 3 | gpu 블록 스키마 | **gpuCount 추가**(필수), gpuType은 **단순 기종 표기**(H100, A100), 검증 `gpuHours ≤ gpuCount × 24` | 미팅 확정 사항 |
| 4 | GPU Hour("가동") 정의 | "실제 쓰인 시간" → **"모델에 GPU가 매핑·할당된 시간"** | 측정 가능한 정의 |
| 5 | 일정 | **~9/18** `/v1/metrics` 구축·대시보드 연동. 그 전까지 수기(엑셀) 취합 | 미팅 확정 사항 |
| 6 | model `unknown` | **test 카테고리에서만 허용** — serving/standby는 금지(정합성 검증 위반으로 알림) | 프로덕션에서 "모델을 모른다"는 성립 불가. unknown이면 분해·배부·효율 산출 전부 불가 |
| 7 | 라지모델 인센티브 | **체급(sizeClass: S ~15B / M ~40B / L 40B+, MoE는 활성 파라미터) 도입** + **효율 랭킹은 체급 내에서만**(체급 간 줄 세우기 금지) + 라지모델 가치는 **채택도**(사용 서비스·사용자 수, 토큰 점유율 추세 — 기존 토큰 API로 산출, 추가 수집 없음)로 표현 | 현 지표 전 축이 라지모델에 불리한 구조적 편향. 비용 숫자는 사실대로, 교정은 표시 계층에서 |
| 8 | 품질 축 | **보류** (AA 인용도 아직 안 함). 2단계에 사내 평가셋/공개 지수(suite 버전 명시) + 비용×품질 프런티어 검토. 다운사이징 의사결정은 프록시가 아닌 **델타 실험**(교체 시 재질문율·채택률 변화)으로 판정 | 품질은 엔진 레벨에서 측정 불가 — 오프라인 평가 트랙(AA 방식)으로만 가능 |
| 9 | 스펙 문서 구조 | 상세본은 **old로 보존**, 담당자 구현 최소셋만 담은 **간소화 스펙** 신설 | 상세본은 대시보드 설계까지 섞여 담당자에게 과함 |
| 10 | gpuCount 존폐 | **유지** — 경영진·인프라 운영의 "몇 장?" 질문에 정수로 답하는 필드. 단 **비용 계산에는 미사용** 명시 | 파생값(평균)은 부분 가동 시 소수가 되어 설명 비용 발생. 보고 부담 사실상 0 |
| 11 | 비용 계산식과 단가 단위 | 모델 비용 = **`Σ기종 (gpuHours × 단가)`**, 단가 단위는 **원/GPU·hour**. 장수는 gpuHours(= 장수 × 시간)에 내장 — 차원 소거: `[GPU·h] × [원/GPU·h] = [원]`. gpuCount × 단가 계산 금지(장수 이중 곱셈) | 단위 혼동 방지 |
| 12 | 하루 내 변동 추적 | 장수 증감은 gpuHours에 반영(적분값), **기종 변경은 gpuType별 행 분리**. 시간대별 프로파일(몇 시에 몇 장→몇 장)은 **의도적 미수집** — 단가가 일 단위 상수라 비용은 적분값으로 정확. 변동 여부는 `gpuHours < gpuCount×24` 플래그로 식별 | (장수, 시간) 쌍으로는 하루 내 변동을 표현할 수 없음 — 적분값만이 정확 |
| 13 | 할당의 정의 | **고정 쿼터** (예약 장수 × 24h). 추론 서비스가 GPU 우선권, 학습은 유휴분 백필. 스케일다운·백필 시간의 비용도 쿼터 보유 서비스 귀속·유휴 표시 → "쿼터를 줄여라"가 절감 신호. 오토스케일링 도입돼도 계약 불변(gpuHours 적분, gpuCount=피크). 백필 학습 구분은 `test`, 2단계 `backfill` category 검토 | 인프라 구조상 추론 우선·학습 백필 형태 |
| 14 | 주간/야간 모델 API (시간 분할 서빙) | **model별 행 분리** (기종 변경과 같은 원리) — 비용은 모델별 gpuHours 비례로 정확 분해. **gpuCount는 행 간 합산 금지**(착시 — 장수 합산은 `Σ gpuHours ÷ 24`). **GPU 할당 단위 하나 = service 하나** 매핑(겹치면 할당 이중 계상) | 행 구조가 model × gpuType × category 단위라 스키마 변경 없이 처리됨 |
| 15 | 모델 크기 수집 방식 | 등급(sizeClass: S/M/L) 직접 기재 → **원시 파라미터 수집**으로 변경: `paramsB`(총 파라미터, B 단위) + MoE는 `activeParamsB`(활성) 병기. 체급(효율 리그)은 운영자가 대시보드에서 파생 — 분류 경계를 시트 계약에 고정하지 않고 추후 자유롭게 조정 | 총=GPU 점유(비용), 활성=토큰당 연산(속도) — 원시 값이 있으면 어떤 분류 체계든 사후 구성 가능. 등급 고정 시 40B+ 한 칸에 70B와 405B가 뭉치는 문제도 해소 |
| 16 | 성능 스크랩 수집기 설계 | **VIP 경유 + `process_start_time` 지문 역다중화** 채택 — 10~30초 주기·매 스크랩 새 연결, 지문별 델타 누적(리셋=start_time 변경), 분 단위 델타 적재 후 daily 버킷 합산. **레플리카 개별 접근·종료 유예(preStop)를 담당자에게 요구하지 않음**(preStop은 권장으로만 — 적용 시 계획 재시작 유실 0). 정합성은 토큰 교차검증·커버리지·리셋 계량·품질 플래그로 자동 감시. 케이스 A~C 팀에도 경로 (a) 선택권 부여 | 사내 LB/VIP·방화벽 관행과 다수 운영 주체 환경에서 강제 불가능한 요구 배제. 누적 카운터는 희소 관측에 무손실이라 VIP 분산 스크랩으로 충분 |
| 17 | GPU 할당 매핑 수집 방식 | 단일 unit 키 → **프리픽스 목록**(`gpuDashboardUnits`)으로 변경 — 계층(`인프라유형:워크그룹:unit이름`)의 어느 수준이든 지정 가능, 프리픽스 아래 unit 자동 포함. 워크그룹 수준 권장, 공유 워크그룹만 unit 수준. 긴 프리픽스 우선 + 동일 unit 이중 매핑 검증 알림 + 미매핑 unit 알림(폐루프) | unit이 모델·배포 단위로 생성·소멸하므로 나열식은 유지 불가 — 프리픽스면 churn에도 시트 갱신 불필요 |
| 18 | 성능 지표 percentile 구성 | TTFT·ITL = **p50/p90/p95/p99** (p95 추가). Output TPS = **p50만** — avg 제거(요청별 비율의 평균은 통계적 왜곡, 총 처리량은 토큰 API에서 파생 가능해 이중 소스 금지에도 해당), 상위 percentile 불요(TPS의 나쁜 꼬리는 낮은 쪽이며 ITL p99가 동일 정보 담당 — 필요 시 2단계에 p10 검토). **성능의 정본은 서비스×모델 단위** — 모델 혼합 percentile은 트래픽 비중에 좌우되어 참고 지표로만, SLO 판정은 모델 단위 | 혼합값은 성능 변화와 트래픽 변화를 구분 못 함 |
| 19 | 비스트리밍·고유 지표 | 케이스 F는 serving 블록 **채움**: **`e2eMs`(표준, 필수) + `custom[]`(자유 지표, 선택)**. custom은 `{name, unit, p50…}` 구조 고정 — unit 필수, 표준 지표로 표현 가능하면 금지, 해당 서비스 화면(개괄·상세)에 표시하되 서비스 간 비교·랭킹·SLO 판정에는 불사용 | 완전 자유형은 파싱·표시 불가 — 구조만 고정하면 임의 지표를 수용하면서 표준 지표의 비교 가능성을 보존. 비스트리밍도 성능 제공 의무는 동일(지표만 다름) |
| 20 | 소비자 식별·GPU 매핑 형식 | ① 서비스 계정(API 키) 매핑 수집 **전면 제거** — 시트 항목·API `serviceAccounts` 자기신고 삭제. 대신 **플랫폼이 키 발급 시 소비 서비스의 `service` 표기를 받아 기록**하고, 토큰 사용량 제공 시 그 표기로 소비자 호출분을 구분 (미등록 표기는 알림 폐루프). ② `gpuDashboardUnits`를 프리픽스 문자열 → **구조화 필드**(`infraType`/`workgroup`/`unit` 선택)로 변경 — unit 비우면 워크그룹 전체 | 키 식별자를 시트·API로 흘릴 이유가 없고, 배부에 필요한 건 사용량 데이터의 소비자 구분자뿐. 수기 엑셀에서 패킹 문자열은 구분자 실수를 유발 |
| 21 | 혼합 구성·케이스 E 의무 (리뷰 반영) | ① 케이스 판별은 **모델×경로 단위** — serving에는 경로 (a) 모델 행만 넣고 스크랩 대상 모델 행은 제외, gpu 블록은 케이스와 무관하게 자체 GPU 전부. ② **케이스 E(사외 AI 모델 API)의 serving 제공은 선택**으로 확정 — §0 의무 표와 케이스 표의 모순 해소. ③ custom 값 키는 p50/p90/p95/p99 한정·최소 1개 | 멀티 엔진 서비스에서 §0·§4 지시가 충돌하던 계약 공백 — 스펙·OpenAPI 리뷰(5렌즈+반박 검증)에서 확인된 결함 수정 |

## 3. 2단계로 미뤄둔 것

- chargeback(실제 정산) 여부 협의, user → 조직 rollup 뷰
- 피크 지표(peakHourRequests, peakGpuCount 등) — *(E2E 지연과 경로 (a) serving 블록은 #16·#19로 1단계에 편입됨)*
- **품질 축**: 사내 평가셋/공개 지수 인용(suite 버전 관리), 비용×품질 프런티어 차트, outcome 자기신고 필드(showback 참고용 한정)
- `backfill` category (학습 백필 구분)
- 하루 내 스케일 곡선 — 담당자 보고가 아닌 중앙 스크랩(k8s/GPU 대시보드)으로
- 관리 정보 등록 화면(웹 폼 + DB) 전환
- 그룹 공통 GPU의 하위 배부, 소비 체인 다단계

## 4. 담당자 관점 한 줄 요약

**엑셀 양식 1회 제출 + GET `/v1/metrics` 1개 구현**(vLLM/SGLang은 URL 제출 + 네트워크 개방만)이 전부이며, 이후에는 중앙 알림에 반응만 하면 되는 구조.
